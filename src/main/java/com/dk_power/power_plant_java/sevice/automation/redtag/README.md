# Red Tag LOTO Automation (rebuilt)

A clean, self-contained rebuild of the SikuliX desktop automation that builds
LOTO procedures in the **Red Tag Enterprise** application. It lives entirely in
this package and does **not** touch the legacy `sevice/automation/` code, which
stays in place as a reference until this version is verified on a real machine.

## Why a rebuild

The legacy `RedTagAutomationService` was a ~1,700-line class: ~200 loose
`Pattern` constants with hard-coded `J:/` paths, magic-number offsets, dead test
methods, and all four permit types tangled together. This version fixes that:

| Concern | Legacy | Here |
|---|---|---|
| Screenshots | ~200 `new Pattern("J:/...")` on a network drive | `RedTagPattern` enum + bundled images in the repo (`PatternCatalog`) |
| Screen API | inline `screen.find(...).offset(...).click()` | `SikuliDriver` — one wrapper, retries, uniform errors |
| Orchestration | mixed into the god class | `StepEngine` — generic, permit-agnostic |
| LOTO flow | semi-auto (app + login + builder opened by hand) | `LoginFlow` + `LotoBuildFlow` — fully automated |
| Failures | stringly-typed `"Failed ..."` | typed `AutomationException` |

## Layout

```
config/    RedTagAutomationProperties   externalised paths / timeouts / credentials
core/      RedTagPattern                enum catalogue of every screenshot
           PatternCatalog               resolves names -> SikuliX Patterns
           SikuliDriver                 thin wrapper over the SikuliX Screen API
           RedTagWindow                 launch / focus / maximise the Red Tag app
           AutomationException          single typed failure
session/   AutomationStep / AutomationSession / StepStatus / SessionStatus
           StepEngine                   runs a session: pause/resume/stop/retry/skip
flow/      LoginFlow                    open app + sign in
           LotoBuildFlow                open builder -> header -> points -> Continue
progress/  RedTagProgressBroadcaster    SSE progress to the browser
RedTagLotoAutomationService             facade: turns a LotoDto into a session
```

Controller: `controller/automation/redtag/RedTagAutomationController` at
`/ng/red-tag-automation/*`.

## Flow: build a LOTO

```
POST /ng/red-tag-automation/loto/{lotoId}/build
  -> RedTagLotoAutomationService.startLotoBuild(LotoDto)
       step 0  open-app      LoginFlow.ensureAppOpen()
       step 1  login         LoginFlow.ensureLoggedIn()
       step 2  open-builder  LotoBuildFlow.openLotoBuilder()
       step 3  fill-header   LotoBuildFlow.fillHeader(loto)
       step 4  add-points    LotoBuildFlow.addPoints(points)
       step 5  finalize      LotoBuildFlow.clickContinue()
  -> StepEngine runs the steps on a background thread
  -> RedTagProgressBroadcaster streams progress over SSE
```

Controls: `POST /pause|/resume|/stop|/retry-step|/skip-step`,
`GET /status`, `GET /stream` (SSE), `POST /manual-confirmation?enabled=`.

## Patterns / screenshots

See `project/features/red-tag-automation/PATTERN_MANIFEST.md`. Images are bundled
at `src/main/resources/automation/redtag/patterns/` and regenerated by
`generate-patterns.py`. Patterns are pixel-real crops — they match the live
screen only at the resolution they were captured at.

## Known scope boundary

`LotoBuildFlow.clickContinue()` stops at the **Continue** button. The
post-Continue "Information" form and the final save / permit-number read-back are
not yet scripted because no screenshots of those screens were supplied. The
manifest explains how to extend it. Hot Work, Confined Space (Reclassified +
Permit Required) and Safe Work are intentionally **not** in this package yet —
they follow the same `flow/` + facade pattern once their screens are captured.
