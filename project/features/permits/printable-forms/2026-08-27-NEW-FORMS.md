## Hot Work rebuild — DONE 2026-08-28

Data model, seeder, web form and daily package all rebuilt to the new design.

- `HotWorkType` POJO + **24 new entity columns**; `isFireWatchRequired` kept but `@Deprecated`
  (superseded by the `fireWatchDuration` tri-state) so existing rows are not reinterpreted.
- Java DTO + `HotWorkMapper` wired both directions, null-guarded.
- Angular model: interface, class, constructor, `toJson`, `fromJson`, `isValidKey`,
  `toTableColumns`, `allFields` — plus the **default `fields` array**, which matters more than it
  looks: the paper form only merges `toFormFields` output into containers whose name is in that
  list (`hot-work-paper-form.component.ts`), so a `select` like `fireWatchDuration` would have
  rendered as an EMPTY dropdown if it were only in `allFields`. Web SmartForm and paper form read
  the same list, which is why "web + printable both work" forces one list rather than two.
- Seeder: page 1 rebuilt; page 2 reduced to static reference (the 4 fire-monitor Time/Reading
  grids are gone from the paper).
- Verified: **56 seeded bindings, 0 unresolved, 0 missing from the default list.**
- Section tags come straight off the paper's own legend — teal = permit issuer (`issuer`),
  purple = performer / fire watch (`ops:worker`) — feeding the agreed edit-lock policy.

### Daily package
Chain verified end to end: `DailyPermitPackageMapper` delegates to `hotWorkMapper` both ways;
Angular package `toJson`/`fromJson` delegate to `HotWorkDto`. All 24 fields flow.

**Bug found and fixed while verifying:** `copyPackage` clears only id/date/workScope/redTagNum.
Because the new fields now round-trip properly (they used to be dropped by accident), a copied
package would have produced a Hot Work permit that was **pre-signed, pre-started and
pre-cancelled**. Added `clearHotWorkExecutionState(dto)`: nulls approvals, the ACTIVE HOT WORK
window, the whole cancellation/monitoring block and the air-test readings, while deliberately
preserving checklist, workType, meter details and fire-protection state (job setup, not execution).
