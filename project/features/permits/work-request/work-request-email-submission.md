## Description

When the PWA cannot submit a work request through the normal channels (Java server unreachable + Power Automate flow fails), the user is presented with an email fallback. The email includes the full work request data plus an auto-submit deep link that allows the receiving operator to submit the request with a single click — if the Java backend is running on their machine.

## Data Flow

```
PWA Form Submit
    ↓ Server unreachable
    ↓ Power Automate fails
Email Fallback UI (form component)
    ├─ "Open Email Client" → mailto: link with WR data + auto-submit link
    ├─ "Open Gmail" → Gmail compose with same body
    ├─ "Submit via Server" → deep link directly to Java backend
    └─ "Download Attachments" → base64 → file download (if any)

Operator clicks auto-submit link (from email or UI):
    ↓
GET /api/pwa/work-request/submit-from-email?data=<base64>
    ↓ Base64 decode → JSON → PwaWorkRequestDto
PwaWorkRequestService.submitWorkRequest(dto)
    ├─ Dedup check (localUuid) → "Already Submitted" page if duplicate
    ├─ Save to local DB
    ├─ Submit to SharePoint (certificate → PA fallback)
    └─ Return HTML result page (success / duplicate / error)
```

## Submission Fallback Chain

The orchestrator (`SubmissionOrchestratorService`) tries methods in order:

| # | Method | Service | Condition |
|---|--------|---------|-----------|
| 1 | Java Server | `ServerApiService.submitWorkRequest()` | Server reachable at `environment.serverUrl` |
| 2 | Power Automate V2 | `PowerAutomateService.submitV2()` | PA flow URL configured and responsive |
| 3 | Email Fallback | Manual — user sends email | Both above failed |

On email fallback, the state service sets `emailFallbackData` signal which triggers the fallback banner UI.

## Email Fallback UI

Located in [work-request-form.component.html](../../../../browser/ng-ui/src/app/features/work-request/work-request-form/work-request-form.component.html).

Buttons:

| Button | Action | Status Set |
|--------|--------|------------|
| Open Email Client | Opens `mailto:` with pre-filled subject, body, and auto-submit link | `sent via email` |
| Open Gmail | Opens Gmail compose in new tab | `sent via email` |
| Submit via Server | Opens deep link to Java backend in new tab | `sent via email` |
| Download Attachments | Downloads each attachment as a file via data URI | — |
| Done | Clears the fallback banner | — |

All email/server buttons call `WorkRequestStateService.markSentViaEmail()` which updates the work request status in IndexedDB and the table.

## Auto-Submit Deep Link

### URL Format

```
{serverUrl}/api/pwa/work-request/submit-from-email?data={base64}
```

- **Dev:** `http://localhost:8082/api/pwa/work-request/submit-from-email?data=...`
- **Prod:** `https://jgportal.jpowerusa.com/api/pwa/work-request/submit-from-email?data=...`

### Encoded Payload

The `data` query param is a base64-encoded JSON matching `PwaWorkRequestDto` (minus attachments):

```json
{
  "localUuid": "a1b2c3d4-...",
  "company": "DK",
  "dateOfWork": "2026-02-11",
  "timeOfWork": "15:20",
  "locationOfWork": "Location",
  "workRequestedBy": "DK",
  "affectedEquipment": "Equipment",
  "workScope": "Scope of work",
  "isLotoRequired": true,
  "isHotWorkRequired": false,
  "isConfinedSpaceEntryRequired": false,
  "foremanName": "",
  "fireWatchName": "",
  "spaceToBeEntered": "",
  "submitterName": "DK",
  "submitterEmail": "dk@company.com",
  "submitterPhone": "555-1234",
  "submitterCompany": "DK",
  "timeSubmitted": "2026-02-11T21:40:54.000Z",
  "attachments": []
}
```

Attachments are excluded (base64 content is too large for URLs). The email body notes the attachment count so the operator knows to request them separately.

### Link Generation

Generated by `SubmissionOrchestratorService.generateSubmitLink(workRequest)`:
1. Builds `PwaWorkRequestDto`-shaped object from WorkRequest fields + `UserSetupService` data
2. `JSON.stringify()` → `btoa()` → appended as `?data=` param
3. Included in email body via `generateEmailContent()` and exposed in form UI via `submitLink` computed signal

## REST API

### Email Deep Link Endpoint

| Method | Path | Produces | Description |
|--------|------|----------|-------------|
| GET | `/api/pwa/work-request/submit-from-email?data={base64}` | `text/html` | Decode + submit + return HTML result |

**Controller:** [PwaWorkRequestController](../../../../src/main/java/com/dk_power/power_plant_java/controller/pwa/PwaWorkRequestController.java)

**Response pages:**

| Scenario | Title | Color |
|----------|-------|-------|
| Success | "Work Request Submitted" | Green (`#d4edda`) |
| Duplicate (same `localUuid`) | "Already Submitted" | Yellow (`#fff3cd`) |
| Error | "Submission Failed" | Red (`#f8d7da`) |

Duplicate protection uses `PwaWorkRequestService.submitWorkRequest()` which checks `workRequestRepo.findByLocalUuid()` before processing.
